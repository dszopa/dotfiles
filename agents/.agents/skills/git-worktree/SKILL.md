# Git Worktree

## Overview

This sop guides agents in creating, using, and cleaning up git worktrees for isolated task work. Use this skill when the user asks you to work in a worktree, on a worktree, or to use a worktree for a task.

## Parameters

- **task_slug** (required): A short, descriptive slug for the task. Generated by slugifying the user's task description: lowercase, hyphens for spaces, strip non-alphanumeric characters except hyphens. Example: "Add user login feature" -> `add-user-login-feature`.
- **task_description** (required): The user's description of the work to be performed in the worktree.
- **base_ref** (optional, default: `HEAD`): The git ref (commit, branch, tag) to base the worktree on. Defaults to current HEAD.

## Steps

### 1. Validate Repository

Check that the current working directory is inside a git repository and that `.git` is a directory (not a submodule or bare repo).

**Constraints:**
- Run `git rev-parse --git-dir 2>/dev/null` to locate the git directory
- If the command fails (no git repo), stop and tell the user this is not a git repository
- If `.git` is not a directory (e.g., it's a file for submodules), stop and tell the user this is a submodule or bare repository and ask how they want to proceed

### 2. Check for Existing Worktree

Check if `.git/agent/<task_slug>/worktree/` already exists.

**Constraints:**
- If the path exists, tell the user: "An existing worktree was found at `.git/agent/<task_slug>/worktree/` on branch `<task_slug>`."
- Ask the user whether to:
  - Resume working in the existing worktree
  - Remove it and create a fresh one
  - Choose a different task slug
- If the user chooses to resume, skip to step 4
- If the user chooses to recreate, remove the existing worktree (and optionally the branch) before proceeding
- If the user chooses a different slug, update `task_slug` accordingly and loop back to this check

### 3. Create Worktree

Create the worktree at `.git/agent/<task_slug>/worktree/` with a new branch named `<task_slug>` based on `base_ref`.

**Constraints:**
- Create the parent directory: `mkdir -p .git/agent/<task_slug>/`
- If `base_ref` is `HEAD`:
  - Run: `git worktree add .git/agent/<task_slug>/worktree/ <task_slug>`
- If `base_ref` was specified by the user:
  - Run: `git worktree add .git/agent/<task_slug>/worktree/ <task_slug> <base_ref>`

**Collision Handling:**
- If the command fails because branch `<task_slug>` already exists, stop and ask the user how to proceed
- If the path already exists (shouldn't after step 2), stop and ask the user how to proceed

**After successful creation, communicate to the user:**

Created worktree at `.git/agent/<task_slug>/worktree/` on branch `<task_slug>` at `<base_ref>` (`<short_commit_hash>`).

### 4. Perform Work

Change to the worktree directory and perform the requested task within it.

**Constraints:**
- Change directory to `.git/agent/<task_slug>/worktree/` for all subsequent operations
- All code changes, commits, and other git operations should happen inside the worktree
- If the task involves other skills or tasks that work on the repo root, the worktree directory is the repo

### 5. Ask About Removal

When the work is finished or near finished, ask the user if they would like to remove the worktree.

**Suggested prompt:**

> The worktree at `.git/agent/<task_slug>/worktree/` on branch `<task_slug>` is ready for cleanup. Would you like to remove it?

- If yes, proceed to step 6
- If no, stop and note that the worktree remains at `.git/agent/<task_slug>/worktree/`

### 6. Remove Worktree

Remove the worktree
**Constraints:**
- First, ensure you are NOT inside the worktree being removed. Change back to the main repo root before running removal commands.
- Run: `git worktree remove .git/agent/<task_slug>/worktree/`
- After removal, ask: "Delete the local branch `<task_slug>` too? (Y/n)"
  - If yes (or enter), run: `git branch -D <task_slug>` (force-delete, local only — never delete from remote)
  - If no, leave the branch intact
- Notify the user when the worktree (and optionally the branch) has been removed

## Artifacts
- `.git/agent/<task_slug>/worktree/`: The worktree checkout directory
- `.git/agent/<task_slug>/`: Namespace for future agent task artifacts (unused by this skill)

## Troubleshooting

### Stale Worktrees
If `git worktree remove` fails because the worktree is locked or has uncommitted changes:
- If locked: run `git worktree unlock .git/agent/<task_slug>/worktree/` and retry
- If uncommitted changes: inform the user and ask if they want to discard changes or keep the worktree

### Detached Worktrees
If the worktree's `.git` file points to a non-existent admin directory, inform the user and suggest manually removing the worktree directory and running `git worktree prune`.
